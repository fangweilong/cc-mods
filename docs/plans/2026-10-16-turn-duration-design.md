# 自定义 TurnDuration 设计

- 日期：2026-10-16
- 状态：设计范围已确认，任务 0–6 已实施；任务 7 文档已完成，真实终端验收待用户运行（2026-10-19）。原始设计背景保留，执行结果见实施计划。
- 实施计划：[2026-10-16-turn-duration-plan.md](./2026-10-16-turn-duration-plan.md)

## 1. 背景与决策

原生耗时行示例：

```text
✻ Baked for 12m 38s · done 15:53
```

当前公开 `TurnDuration` 渲染接口只提供 `word`、`durationMs` 和可选的只读 `onScreen`。仅改写 `word` 无法翻译宿主后续拼接的 `for`、`done`；`next(e)` 返回的是原生绘制引用，也无法遍历出内部文字再翻译。

旧实现直接绘制“已完成，用时 …”，但没有接管显示条件与状态数据，导致后台等待、隐藏设置、可选统计和条件间距失真。设计时工作区已移除这段自绘、恢复原生渲染，作为安全基线；后续任务 0–6 在该基线上实施下述默认原生、手动启用的自定义方案。

本方案选择：**在用户明确启用后，由 Mod 接管该位置的渲染与显示策略，复用现有 i18n 语言选择；能够可靠取得的数据才展示，不能取得的数据不伪造。**

这里的“接管”是自定义组件拥有自己的显示契约，不等于已经能完全复刻原生所有内部行为。

## 2. 用户约束

1. 不修改、替换、重新签名宿主可执行文件。
2. 不改变启动器、启动路径或现有启动配置。
3. 仅使用公开 Mod API，不依赖二进制偏移、私有状态或终端输出替换。
4. 不改写用户消息、模型回复、工具结果及会话中的原始记录。
5. 只在语言包中存放文案数据，不执行语言包中的代码、正则或任意表达式。
6. 保留已有 Spinner、PromptHint、InfoNotice 等翻译与当前工作区的相关修改。

## 3. 目标与非目标

### 3.1 最终目标

提供一条可完整中文化、可配置、行为明确的耗时行。逐步补充完成时刻、后台等待和可选统计，但每项能力必须先取得可靠数据来源。

### 3.2 第一版目标

第一版仅依赖现有渲染输入，提供以下能力：

- 原生模式与自定义模式切换。
- 使用 `durationMs` 渲染中性的“本轮用时 …”，不以此推断所有任务已经完成。
- 复用现有语言包与语言切换、重新加载机制。
- 独立控制自定义行的显示及顶部间距。
- 保留原生模式作为快速回退路径。

第一版中文示例：

```text
✻ 本轮用时 12m 38s
```

### 3.3 第一版不承诺

- 与原生所有隐藏状态、统计和间距逐项等价。
- 自动继承未公开的原生 `showTurnDuration` 开关。
- 展示原生精确完成时间。
- 复刻后台 Agent、Workflow、远端任务、通知队列的完整计数口径。
- 展示预算、预算提醒、隐藏消息数。
- 多端同步实现。`TurnDuration` 当前只在 terminal 触发。

**如果产品要求“完整中文且与原生全部行为等价”，第一版不能按此标准宣称完成；必须先解决数据能力缺口。**

## 4. 已核实的能力边界

以下结论基于本机 2.1.300 的公开类型契约。契约位置由 `plugin-authoring` skill 提供，不在仓库中复制生成的类型文件。

| 数据或能力 | 核验结论 | 本方案处理 |
| --- | --- | --- |
| `word` | 渲染输入提供 | 第一版不依赖它推断完成状态，也不维护完成词白名单 |
| `durationMs` | 渲染输入提供 | 第一版耗时的唯一数据来源 |
| `onScreen` | 可选、只读，表示视口范围 | 不改写，不当作隐藏设置或任务状态 |
| `requestId` | 有渲染实例标识 | 不假设它等于消息 UUID 或 `turnId` |
| `turn.start` / `turn.complete` | 通过 `turnId` 关联；complete 有耗时、可选 agentId 等字段 | 第一版不需要订阅，也不拿它与渲染实例猜测配对 |
| 原生结束 timestamp | 上述事件及公开渲染输入未提供 | 第一版不显示结束时刻 |
| 会话消息读取 | 公开消息视图没有原生 duration 记录的完整元数据 | 不通过读取历史补出原生 timestamp、预算等字段 |
| `session.append` | 有稳定 UUID，但明确不暴露原始 timestamps | 不用追加事件的接收时间冒充原生完成时间 |
| `agent.list` | 不是完整后台队列；部分 Workflow、引擎 fork 不对应列表行 | 不用于原生后台总计或判断“全部完成” |
| 原生隐藏设置 | config 只列出可见配置行，尚未证明能读取 `showTurnDuration` | 自定义模式明确使用独立可见性配置 |
| 原生 `addMargin` | 未公开 | 自定义模式明确使用独立间距配置 |

类型核验定位：`RenderInputOf` 约 10109–10141 行，`TurnDuration` 约 10531–10556 行，`session.append` 约 10961–10995 行，会话消息视图约 11596–11622 行，回合生命周期约 13911–14040 行。

此前已确认：原生耗时组件内部才执行隐藏、等待、统计与间距分支。因此自定义模式必须披露其独立行为，不能声称“只改文字，其他自动继承原生”。

## 5. 模块归属

第一版直接放在 `i18n-mod` 内，作为独立的内部模块，**暂不新增单独插件**。

原因：

- 可以直接复用当前语言选择状态和语言包加载逻辑。
- 不需要额外的跨插件依赖、语言同步与配置缓存。
- 当前只有这个组件需要该逻辑，先保持实现范围最小。

建议分工：

| 文件 | 职责 |
| --- | --- |
| `i18n-mod/hooks/register.ts` | 注册事件；读取语言和配置状态；决定回退或接管；所有 `$` I/O 留在这里 |
| `i18n-mod/hooks/turn-duration.ts`，新增 | 纯配置规范化、耗时格式化、视图模型与合法渲染树构造；不访问 `$` |
| `i18n-mod/types/index.d.ts` | 配置、文案类型及需要订阅的 `PluginState` 契约 |
| `i18n-mod/hooks/language.ts` | 新文案命名空间的白名单及模板校验 |
| `i18n-mod/locales/zh-CN.json` | 中文模板 |
| `cc-mods-config/hooks/register.ts` | 在现有“语言与时间”区域提供设置入口 |

不为第一版引入通用模板引擎、独立后台状态服务或新的持久化配置文件。

## 6. 配置契约

下列键在设计时拟新增，现已由任务 3 通过 `i18n-mod` 的 `userConfig` 声明，并由任务 6 接入统一面板；真实终端生效行为仍待任务 7 用户验收。

| 配置键 | 值 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `i18n-mod.turnDurationMode` | `native` / `custom` | `native` | 原生透传或自定义接管 |
| `i18n-mod.turnDurationVisible` | boolean | `true` | 只控制自定义整行是否显示 |
| `i18n-mod.turnDurationSpacing` | `compact` / `separated` | `compact` | 自定义顶部间距分别为 0 / 1 |

规则：

1. 默认 `native`，避免升级后静默替换现有界面；用户手动选择 `custom` 才启用。
2. `native` 模式不解释可见性或间距设置，直接 `next(e)`。
3. English 原文模式继续遵守现有 `preserveOriginal` 契约：即使选中了 `custom`，也交回原生，不应用自定义可见性和间距。
4. 自定义模式不承诺继承原生耗时开关；面板必须明确提示其独立性。
5. `turnDurationVisible=false` 表示隐藏自定义整行，不是只隐藏耗时数字；不能在此分支调用 `next(e)`，否则原生行可能重新出现。
6. 关闭自定义模式只需把 mode 切回 `native`，不需要重启、不需要改安装文件。
7. 配置校验失败或宿主拒绝保存时，保留已生效状态，不提前修改当前显示。
8. 使用宿主配置保存和锁定机制；不把这些设置写入其他 Mod 的 JSON 文件。

## 7. i18n 契约

### 7.1 第一版语言包结构

`turnDuration` 命名空间已由任务 1 加入 schema，任务 5 加入内置中文文案。最小示例：

```json
{
  "id": "zh-CN",
  "name": "简体中文",
  "turnDuration": {
    "elapsed": "本轮用时 {duration}"
  }
}
```

这是第一版已接受的 schema；`turnDuration` 和 `elapsed` 都可省略，显式无效模板拒绝加载，缺失模板留给渲染路径整行回退原生（隐藏分支优先）。

第一版只开放 `elapsed`：

- 可选字符串，存在时必须含 `{duration}`。
- 仅允许约定的占位符，不执行表达式。
- 沿用现有安全控制字符校验和回调替换方式。
- 没有该模板或模板为空时，整行回退原生，避免意外产生混合语法。
- 不读取旧 `completed`、`duration` 字段拼接新组件；旧字段仍接受原有校验，保持加载兼容。
- 不在渲染时加载语言文件；继续复用当前包的状态与订阅。

### 7.2 文案语义

第一版固定使用“本轮用时”，不使用“全部完成”“任务已完成”等推断性文案。它只说明这个耗时记录，不说明后台任务状态。

第一版保留 `d`、`h`、`m`、`s` 紧凑单位；完整句子没有原生 `for`、`done`，但不同时引入单位本地化和日期格式化系统。

### 7.3 后续扩展

先前盘点的完整范围可整理为约 10 类模板：完成耗时、完成时刻、等待句、后台 Agent 数量、动态 Workflow 数量、连接词、预算用量、预算提醒、隐藏消息、仍运行任务。

这些模板只有在对应数据能力通过验证后才进入正式 schema。第一版不提前接受尚未实现的配置键或模板键。

## 8. 渲染决策

决策顺序：

1. 原文模式或 `mode=native`：以原事件调用 `next(e)`，不改任何 props。
2. 已启用自定义且 `visible=false`：返回合法的零内容渲染树；实测必须不占额外行，不透传原生。
3. 模板缺失，或 `durationMs` 非有限值、负数：以原事件回退原生。
4. 其他情况：根据 `durationMs`、模板及间距配置生成自定义树。

自定义树要求：

- 全宽行，`✻` 符号区至少两列，正文淡色。
- 仅从配置选择 `marginTop: 0` 或 `1`，不猜测原生 `addMargin`。
- 不追加原生 engine 节点，避免自定义和原生显示两次。
- 不把 `onScreen=null` 解释为“应该隐藏”；遵守宿主已有虚拟滚动语义。
- 构造失败时依靠明确回退路径，不在每次重绘弹 toast。

耗时格式化是组件自己的显示契约：对有效非负毫秒按秒向下取整，使用紧凑单位；必须测试秒、分钟、小时、天的边界。显示值来自本次渲染输入，不重新计算模型耗时或“扣除工具时间”。

## 9. 状态与生命周期

第一版只需要当前语言选择和当前组件配置：

- 使用 `$.state` 中声明的状态，并通过读取形成重绘订阅。
- 配置在启动时初始化；成功保存后更新对应状态，触发相关渲染。
- 热重载后不能依赖模块变量保留关键数据。
- 不使用定时轮询，不读取完整会话历史，不在渲染时枚举 Agent。
- 不需要维护按回合增长的计时 Map，不需要为第一版落盘回合元数据。

**结束时间不作为第一版状态项。** 后续若增加它，必须先证明渲染实例与结束记录的一一对应关系，并覆盖并行 Agent、恢复会话和热重载；不得把“最近一次 complete”绑定到任意耗时行，也不得在重绘时取当前时间。

## 10. 配置面板集成

复用现有 `/my-cc-mods-config` 的“语言与时间”区域：

- 模式：原生 / 自定义耗时行。
- 自定义行：显示 / 隐藏。
- 顶部间距：紧凑 / 留一行。
- 语言仍使用现有 i18n 语言选择，不增加第二份语言设置。

面板必须可见地说明：

> 自定义模式使用独立显示设置；第一版不显示原生结束时刻、后台等待及预算等统计。需要完整原生行为时，请切回原生模式。

通过 `$.config.list/set` 使用实际加载插件提供的配置行，处理插件未加载、宿主策略锁定、保存失败和部分保存成功。延续现有草稿/保存方式，不混入状态栏配置文件。

## 11. 与其他 Mod 的关系

- 自定义模式会接管该渲染位置，下游同位置 hook 的行为受链顺序影响，文档应明确说明。
- 原生模式必须继续链路，不强制覆盖其他 Mod。
- 不顺带改变 `timestamp-mod` 的时间戳行为，也不复用其“当前接收时间”冒充原生 footer 时间。
- 现有 PromptHint 交互保护与翻译白名单逻辑保持不动。

## 12. 测试与验收

### 第一版必要验收

- 默认原生模式维持当前透传测试全部通过。
- 启用自定义中文后，已知或未知 `word` 都输出中性耗时句，不依赖词表。
- 自定义句子没有宿主追加的 `for`、`done`。
- `visible=false` 不留下文字、前缀或额外空白行。
- 两种间距可测，不固定增加顶部空行。
- English、缺失模板、非法耗时等按本设计回退；原事件、只读信息不被修改。
- 切换语言、重新加载语言包、切换模式和热重载后行为一致。
- 公开 API 未提供的时间、预算及任务状态不出现在输出中。
- 不修改宿主、启动器、消息记录或其他 Mod 的显示行为。

### 必须覆盖的运行时检查

除单元和 Mod 测试外，使用用户现有运行方式验证真实终端：隐藏是否零占位、窗口宽度变化、窄窗口换行、滚动后重绘以及模式切回原生。现有测试中模拟下游原生输出的 fixture 不等同于原生全状态集成测试。

## 13. 后续能力的准入条件

| 能力 | 加入前必须证明 |
| --- | --- |
| 结束时刻 | 有可靠时间来源及与该渲染实例的稳定关联；历史恢复可正确回退 |
| 后台等待 | 数据覆盖实际需要统计的任务类型，能区分前台回合结束与后台仍运行 |
| 原生隐藏设置同步 | 能通过受支持接口读取并追踪变化，而不是猜测或读取安装内部文件 |
| 预算与提醒 | 有原生记录对应的可信字段及单位、阈值语义 |
| 隐藏消息数 | 有与该行一致的统计范围，不能用整个会话消息数替代 |
| 自动间距 | 有明确上下文输入；拿不到时继续提供显式间距设置 |

不能证明的能力留在未支持清单。不得因为“完整接管”而自动假定这些数据已经可用。

- 第一版发布说明明确：新增的是自定义耗时组件，不是无损替换原生所有行为。
- 同步更新插件 README 与根 README，分别描述两种模式的功能和限制。
